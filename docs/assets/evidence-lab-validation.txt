## Interpretation

Feedback labels are synthetic and template-derived. Categories overlap: signup failures can also be reliability failures, and unclear signup instructions can also be usability problems. Twelve disagreements are retained. **94% is agreement with these authored synthetic labels, not with 200 independently labeled customer comments.** Synthetic segment tags do not establish fairness or real customer-segment performance.

The incidents are synthetic vendor-style scenarios, not actual production outages. All source IDs and selected checks were validated, but valid citations alone do not prove semantic support. Human review remains necessary.

Network medians were approximately 0.0229 seconds for inspect-then-recover and 0.0196 seconds for direct reviewed recovery. These measure local software operations, not human alert-to-recovery. The historical résumé results of 30→12 minutes, 92%, 8→3 minutes, and 10→6 minutes have not been copied into the rebuild's measurements.

## Verification boundaries

- The application and monitoring are local; no public website is claimed.
- Docker Compose was validated, but its engine was unavailable. Checksum-verified portable Windows Prometheus and Grafana were run instead.
- Windows restricted alert-rule path resolution and dashboard file provisioning. The active portable stack uses `--metrics-only`; alert definitions passed Promtool validation separately. The dashboard was imported through Grafana's authenticated local API.
- Ansible playbooks and GitLab CI configuration are supplied. They have not run in Linux/WSL or remote GitLab here; WSL access was denied.
- SNMP v2c was exercised against the loopback lab agent. No physical router, production endpoint, or remote recovery was accessed.
- Responsive CSS is implemented; exhaustive mobile/accessibility certification is not claimed.
- Independent human timing studies and semantic-support review remain to be conducted with the supplied protocol and empty records.
